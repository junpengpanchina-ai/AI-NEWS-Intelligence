# WorldMonitor 架构参考（PJ Intelligence V0.2）

本文只记录 [koala73/worldmonitor](https://github.com/koala73/worldmonitor) 的公开产品结构，以及它对 PJ Intelligence V0.2 的取舍。不收录其源码、协议定义、授权实现或可运行片段。

公开材料主要来自该仓库的产品说明、架构说明，以及 worldmonitor.app 的产品介绍。观察日期：2026-10-05。

PJ Intelligence V0.1.1 仍是本地看板：公开源采集、`raw_items` 去重、本地打分、用户点击后单条研判，结果写入 `ai_analysis`。V0.2 不改这条链路的触发方式。

## 1. WorldMonitor 的核心模块

WorldMonitor 是一个实时全球情报台。它把多类公开信号收进同一操作画面，再用地图和一组专用面板一起看，而不是只做新闻列表。

### Data sources

数据源是登记在册的上游，不是临时写死的几个 URL。覆盖新闻、冲突、市场、航运、航空、网络、气候、能源和基础设施等。每个源有提供者、采集方式和许可姿态。采集失败时跳过该源，并留下可观察的缺口，而不是让整次刷新失败。

源还有层级：通讯社、主要媒体、专业源、聚合源的权重不同。状态媒体可以收录，但要标出宣传风险，不能和独立报道混成同一可信度。

### Map / globe

画面中心是地图。同一套图层目录同时供给三维地球和平面 WebGL 地图。冲突、军事、抗议、灾害、航运、基础设施等以不同类型的点叠在同一地理表面上。聚类、距离和热点都围绕“同一地点是否同时出现多种信号”。

### Panels

地图旁边是面板库存。每类信号有自己的面板，而不是一个无限滚动的混合列表。面板可以按变体重排，布局可保存。面板之间用事件通信，例如突发消息和主题切换，而不是互相直接改对方的内部状态。

### Correlation

相关性是产品核心：单一来源不够格升级。焦点需要新闻、军事、市场、抗议等独立信号在同一地区或同一主题上汇合。关键词飙升、热点和军事活动可以进入异常检测，但不自动等于一条已核实的突发结论。

国家不稳定指数一类的分数把“不稳定”拆成可分开看的分量，并和约 24 小时前的快照比较。原始计数如果不对照基线，就不作为警报。

### Variants

一套代码生成多个站点变体：地缘（World）、科技（Tech）、金融（Finance）、大宗商品（Commodity）、正面新闻（Happy）、能源（Energy）。变体切换的是默认源、面板、图层、刷新节奏和品牌，不是再做六个产品。

### Local AI

模型调用排在规则之后。关键词分类先给出即时结果，大模型异步修正，用户不必等模型才看到看板。本地路径优先：Ollama，然后才是云端模型，浏览器里还有小型摘要模型作为兜底。没有密钥时，静态图层和本地规则仍可用。世界简报读取已经算好的快照，不在每次打开页面时现调模型。

### API / MCP / CLI / SDK

对外有四层入口，指向同一套情报能力：

- REST，带 OpenAPI 契约
- MCP，供外部代理按工具拉取实时数据
- CLI，在终端里列工具和调用
- 多语言 SDK

工具目录可以公开查看。真正读数据的调用需要密钥或 OAuth，并有配额。这是产品化分发层，不是看板本身。

### Desktop app

桌面端用 Tauri 包一层原生壳，里面仍是同一套 Web 界面。本地 sidecar 转发接口，密钥放在操作系统钥匙串。云端不可用时再回退到线上接口。离线只缓存地图瓦片，情报数据仍要求新鲜拉取。

## 2. 对 PJ Intelligence 可借鉴的模块

V0.2 只借工作方法，把现在的“单条资讯”提升成“事件”，再从事件里读出趋势。

### Source registry

V0.1 已有 `sources` 表。V0.2 把它当成登记册来用：名称、类型、地址、权重、是否启用，并补上最近成功时间、最近错误、连续失败次数。某个源失败只记录错误并继续其他源。权重继续只参与本地打分，不交给模型。

### Freshness tracking

每条 `raw_items` 已有 `fetched_at` 和 `published_at`。V0.2 按源汇总新鲜度，而不是只在列表里看单条时间。状态足够用四档：新鲜、变旧、无数据、错误。顶部统计和 Signals 继续读同一份计数。源过期时明示缺口，不用空白冒充“今天没有事”。

### Event clustering

世界监视器把多篇报道收成一个新闻簇，规则在本地完成，模型不参与归并。PJ 的对应物是事件：同一标题族、同一链接故事、或短时间窗口内高度重合的 `raw_items`，归入一个 event。去重仍先用现有的 URL 和 `content_hash`。聚类只处理已经入库的条目，不在采集时调用模型。

### Panel inventory

保持现在的四块，不新增地图或第二种站点：

- Trend Radar：关键词计数
- Hot Now：高分条目
- Signals：今日、高分、来源
- Intelligence Panel：单条详情和手动研判

V0.2 只增加一个事件列表的位置，让 Hot Now 能从“单条”切到“事件”。面板职责不合并，避免一个区域同时承担列表、统计和研判。

### Intelligence brief

简报是对一个事件的短结论，不是对全库的自动综述。输入只来自该事件已关联的条目：标题、来源、链接、摘要。输出仍是中文、可核对、避免空话。生成时机与 V0.1 相同：用户点击之后才调用模型。已有简报先读本地缓存。

### Manual analysis cache

`ai_analysis` 继续作为单条资讯的手动研判缓存。事件级结论另表存放，不覆盖单条结果。打开页面、刷新、采集、切换条目，都只读缓存。按钮在已有结果时显示“重新研判”，没有结果时显示“AI 研判”。

## 3. 明确不要复制的模块

| 模块 | 不放入 V0.2 的原因 |
| --- | --- |
| 复杂地图 / 地球 | PJ 的对象是商业与技术信号，不是地理态势。地图会改变信息架构。 |
| 桌面端 | 本地 Docker 看板已够用。不引入原生壳、sidecar 或系统钥匙串。 |
| 多语言 | 界面保持中文。不做语言包、RTL 或按语言拆站。 |
| MCP / SDK / CLI 产品层 | 不把看板做成对外代理平台，也不发布客户端库。 |
| 商业授权相关代码 | 不复制付费墙、结算、席位、配额商品或 Pro 账号流程。模型额度仍只用本地的每日上限。 |
| WorldMonitor 原始源码 | 不 Fork、不粘贴实现、不照搬协议文件和面板类。本文只保留模块边界。 |

许可方面，WorldMonitor 公开仓库使用 AGPL-3.0。PJ 不把它的代码并入本仓库，因此也不继承它的授权实现。

## 4. V0.2 目标：Raw Item → Event → Trend

```text
公开源
  → Raw Item     一条已去重的资讯，沿用 raw_items
  → Event        若干 Raw Item 组成的同一件事
  → Trend        一段时间内仍在增强的 Event，由本地分数排序得出
```

三条规则：

1. Raw Item 只表示“我们看到了一条报道”。它不直接等于趋势。
2. Event 表示“这些报道在讲同一件事”。归并用标题、链接和来源多样性，在本地完成。
3. Trend 不是新表，也不是新的采集任务。它是查询：最近时间窗内，`event_scores` 高、关联条目在增加、来源不少于两个的 Event。

模型不参与这三步的生成。它只在用户打开某个 Event 并点击研判时，为该 Event 写一份简报。

## 5. V0.2 最小数据表

下面四张表是新增表。`sources`、`raw_items`、`ai_analysis`、`llm_usage` 保持不动。

### events

一件事的当前状态。

| 列 | 含义 |
| --- | --- |
| id | 主键 |
| title | 事件标题，取关联条目中最早或最清晰的一条 |
| summary | 本地拼接的短摘要，可为空 |
| status | `open` 或 `closed` |
| first_seen_at | 关联条目里最早的 `published_at`，没有则用 `fetched_at` |
| last_seen_at | 关联条目里最新的时间 |
| created_at | 事件创建时间 |
| updated_at | 最近一次归并时间 |

### event_items

Raw Item 与 Event 的多对一关系。同一条资讯只属于一个事件。

| 列 | 含义 |
| --- | --- |
| id | 主键 |
| event_id | 对应 `events.id` |
| item_id | 对应 `raw_items.id`，唯一 |
| is_primary | 是否作为事件标题来源 |
| created_at | 归入时间 |

### event_scores

本地分数的历史。每次重算插入一行，读取时取该事件最新一行。不调用模型。

| 列 | 含义 |
| --- | --- |
| id | 主键 |
| event_id | 对应 `events.id` |
| score | 0–100 |
| item_count | 参与计分的条目数 |
| source_count | 不重复来源数 |
| recency_score | 时间分量 |
| computed_at | 计算时间 |

分数仍由本地规则组成：来源权重、关键词、新旧、来源数量。来源只有一个时，分数封顶，避免单篇稿件变成趋势。

### event_analysis

事件级手动研判缓存。结构对齐现有 `ai_analysis`。

| 列 | 含义 |
| --- | --- |
| id | 主键 |
| event_id | 对应 `events.id` |
| model | 当次使用的模型名 |
| analysis | 中文简报正文 |
| created_at | 写入时间 |

同一事件可以有多行。展示时取最新一行。没有记录就表示尚未研判，不在采集或刷新时补写。

## 与 V0.1.1 的边界

V0.2 开始时仍做这几件事：

- 采集失败的源只记错误
- 页面加载、刷新、采集都不调用模型
- 密钥只留在 `.env`
- 已有单条研判继续从 `ai_analysis` 读取

V0.2 先不做：地图、桌面端、多语言、对外 API、自动批量研判、付费账号。
